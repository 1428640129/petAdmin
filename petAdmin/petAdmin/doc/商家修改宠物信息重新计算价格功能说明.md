# 商家修改宠物信息重新计算价格功能说明

## 功能概述

商家可以在确认预约后、服务开始前，修改宠物的体重和类型（长毛/短毛），系统会自动重新计算价格并更新订单金额。

## 业务场景

1. **用户填写不准确**：用户提交预约时，可能对宠物体重估计不准确
2. **实际检查发现差异**：商家实际检查宠物时，发现体重或类型与用户填写不一致
3. **价格需要调整**：长毛和短毛的价格不同，需要根据实际情况调整

## 数据库变更

### 1. 预约表添加字段
```sql
ALTER TABLE `pet_bath_appointment` 
ADD COLUMN `pet_type` char(1) DEFAULT '0' COMMENT '宠物类型（0=短毛,1=长毛）' AFTER `pet_weight`;
```

### 2. 价格表添加字段
```sql
ALTER TABLE `pet_bath_service_price` 
ADD COLUMN `pet_type` char(1) DEFAULT '0' COMMENT '宠物类型（0=短毛,1=长毛）' AFTER `service_id`;
```

## API接口

### 1. 更新宠物信息并重新计算价格
**接口**: `PUT /bath/appointment/updatePetInfo/{appointmentId}`

**请求参数**:
```json
{
  "petWeight": 5.5,  // 新的宠物体重（kg），可选
  "petType": "1"  // 新的宠物类型（0=短毛,1=长毛），可选
}
```

**响应示例**:
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "success": true,
    "newPrice": 128.00,
    "oldPrice": 98.00,
    "orderUpdated": true,
    "message": "价格已更新"
  }
}
```

**业务规则**:
- 只有在 `pending`（待确认）或 `confirmed`（已确认但未支付）状态下可以修改
- 如果订单已创建且未支付，会自动更新订单价格
- 如果订单已支付，价格无法修改（返回提示信息）

### 2. 计算价格（带宠物类型）
**接口**: `GET /bath/service/calculatePriceWithType?serviceId=1&petType=1&weight=5.5`

**参数说明**:
- `serviceId`: 服务ID
- `petType`: 宠物类型（0=短毛,1=长毛）
- `weight`: 宠物体重（kg）

**响应示例**:
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": 128.00
}
```

## 价格计算逻辑

### 价格表结构
价格表 `pet_bath_service_price` 现在包含以下字段：
- `service_id`: 服务ID
- `pet_type`: 宠物类型（0=短毛,1=长毛）
- `weight_min`: 最小体重
- `weight_max`: 最大体重
- `price`: 价格

### 计算规则
1. 根据服务ID、宠物类型、体重范围查询对应的价格
2. 长毛和短毛可以有不同的价格梯度
3. 如果找不到匹配的价格，返回0

### 示例价格配置
```sql
-- 短毛小型犬（0-5kg）
INSERT INTO pet_bath_service_price(service_id, pet_type, weight_min, weight_max, price) 
VALUES (1, '0', 0, 5, 68);

-- 短毛中型犬（5-10kg）
INSERT INTO pet_bath_service_price(service_id, pet_type, weight_min, weight_max, price) 
VALUES (1, '0', 5, 10, 98);

-- 长毛小型犬（0-5kg）- 价格更高
INSERT INTO pet_bath_service_price(service_id, pet_type, weight_min, weight_max, price) 
VALUES (1, '1', 0, 5, 88);

-- 长毛中型犬（5-10kg）- 价格更高
INSERT INTO pet_bath_service_price(service_id, pet_type, weight_min, weight_max, price) 
VALUES (1, '1', 5, 10, 128);
```

## 业务流程

### 场景1：确认预约前修改
1. 用户提交预约（体重可能不准确）
2. 商家查看预约，发现体重或类型不对
3. 商家调用 `updatePetInfo` 接口修改
4. 系统重新计算价格，更新预约的预计价格
5. 商家确认预约，创建订单（订单价格为新价格）

### 场景2：确认预约后、支付前修改
1. 预约已确认，订单已创建（状态：unpaid）
2. 商家发现体重或类型不对
3. 商家调用 `updatePetInfo` 接口修改
4. 系统重新计算价格
5. 更新预约的预计价格
6. **同步更新订单的总金额**
7. 用户支付时，支付新价格

### 场景3：已支付后修改（不允许）
1. 订单已支付（状态：paid）
2. 商家发现体重或类型不对
3. 调用 `updatePetInfo` 接口
4. 系统返回错误：订单已支付，价格无法修改
5. 需要在完成服务时，通过 `completeService` 接口传入实际价格来处理价格差异

## 代码实现位置

1. **Service接口**: `IPetBathAppointmentService.updatePetInfoAndRecalculatePrice()`
2. **Service实现**: `PetBathAppointmentServiceImpl.updatePetInfoAndRecalculatePrice()`
3. **Controller**: `PetBathAppointmentController.updatePetInfoAndRecalculatePrice()`
4. **价格计算**: `IPetBathServiceService.calculatePrice(serviceId, petType, weight)`

## 注意事项

1. **状态检查**：只有在特定状态下才能修改
2. **订单同步**：如果订单已创建，需要同步更新订单价格
3. **价格验证**：如果无法计算价格，会抛出异常
4. **默认值处理**：如果petType为空，使用原值或默认值（0=短毛）
5. **事务处理**：使用 `@Transactional` 确保数据一致性

## 使用示例

### 前端调用示例
```javascript
// 更新宠物体重和类型
uni.request({
  url: '/bath/appointment/updatePetInfo/123',
  method: 'PUT',
  data: {
    petWeight: 6.5,
    petType: '1'  // 1=长毛, 0=短毛
  },
  success: (res) => {
    console.log('新价格:', res.data.newPrice);
    console.log('旧价格:', res.data.oldPrice);
    if (res.data.orderUpdated) {
      console.log('订单价格已更新');
    }
  }
});
```
