# 预约到订单业务流程设计

## 业务流程概述

### 1. 预约流程状态
```
pending（待确认） → confirmed（已确认） → in_service（服务中） → completed（已完成）
                                    ↓
                              cancelled（已取消）
```

### 2. 订单流程状态
```
unpaid（待支付） → paid（已支付） → in_service（服务中） → completed（已完成）
        ↓                ↓
   cancelled（已取消） refunded（已退款）
```

## 详细业务流程

### 阶段一：用户提交预约
1. **用户操作**：用户填写预约信息（宠物信息、服务类型、预约时间等）
2. **系统操作**：
   - 创建预约记录，状态为 `pending`
   - 根据宠物体重和服务类型计算预计价格（expectedPrice）
   - 生成预约单号（appointmentNo）
3. **结果**：预约记录创建成功，等待商家确认

### 阶段二：商家确认预约
1. **商家操作**：商家查看预约，确认可以提供服务
2. **系统操作**：
   - 将预约状态更新为 `confirmed`
   - **自动创建订单**（订单状态为 `unpaid`）
   - 订单金额 = 预约的预计价格（expectedPrice）
   - 订单关联预约ID（appointmentId）
3. **结果**：预约已确认，订单已创建，等待用户支付

### 阶段三：用户支付订单
1. **用户操作**：用户支付订单
2. **系统操作**：
   - 调用支付接口完成支付
   - 更新订单状态为 `paid`
   - 记录支付时间（payTime）
   - 更新已支付金额（paidAmount = totalAmount）
   - 更新预约状态为 `confirmed`（如果还未确认）
3. **结果**：订单已支付，可以开始服务

### 阶段四：开始服务
1. **商家操作**：商家开始为宠物提供服务
2. **系统操作**：
   - 更新预约状态为 `in_service`
   - 更新订单状态为 `in_service`
3. **结果**：服务进行中

### 阶段五：完成服务
1. **商家操作**：服务完成，确认实际价格（可能和预计价格不同）
2. **系统操作**：
   - 更新预约状态为 `completed`
   - 更新订单状态为 `completed`
   - 记录实际价格（actualPrice）
   - 如果实际价格 > 已支付金额，需要补差价
   - 如果实际价格 < 已支付金额，需要退款
   - 记录完成时间（completeTime）
3. **结果**：服务完成，订单完成

## 异常流程

### 取消预约（在确认前）
1. **用户/商家操作**：取消预约
2. **系统操作**：
   - 更新预约状态为 `cancelled`
   - 记录取消原因和取消时间
   - **不创建订单**（因为还未确认）
3. **结果**：预约已取消，无订单

### 取消订单（在支付后，服务前）
1. **用户操作**：申请取消订单
2. **系统操作**：
   - 更新订单状态为 `cancelled`
   - 更新预约状态为 `cancelled`
   - 触发退款流程（退款金额 = 已支付金额）
   - 更新订单状态为 `refunded`
   - 记录退款金额（refundAmount）
3. **结果**：订单已取消，退款处理中

### 退款（服务完成后）
1. **用户操作**：申请退款（如服务不满意）
2. **系统操作**：
   - 更新订单状态为 `refunded`
   - 记录退款金额和退款原因
   - 调用退款接口
3. **结果**：退款完成

## 关键业务规则

1. **订单创建时机**：预约确认时自动创建订单
2. **价格处理**：
   - 预计价格（expectedPrice）：预约时根据体重计算
   - 实际价格（actualPrice）：服务完成后确定
   - 订单总金额（totalAmount）：初始等于预计价格，服务完成后更新为实际价格
3. **状态同步**：
   - 预约和订单状态需要保持同步
   - 订单状态变化时，同步更新预约状态
4. **支付处理**：
   - 订单创建后，用户才能支付
   - 支付成功后，才能开始服务
5. **退款处理**：
   - 服务前取消：全额退款
   - 服务后退款：根据实际情况退款

## 数据库关联

- `pet_bath_order.appointment_id` → `pet_bath_appointment.appointment_id`
- 一个预约对应一个订单（1:1关系）
- 订单创建后，预约和订单状态需要同步更新
