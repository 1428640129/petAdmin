# 预约到订单业务流程实现说明

## 一、核心业务流程

### 1. 用户提交预约
**接口**: `POST /bath/appointment`
**业务逻辑**:
- 用户填写预约信息（宠物信息、服务类型、预约时间等）
- 系统根据宠物体重和服务类型计算预计价格（expectedPrice）
- 创建预约记录，状态为 `pending`（待确认）
- 生成预约单号（appointmentNo）

**代码位置**: `PetBathAppointmentServiceImpl.insertBathAppointment()`

### 2. 商家确认预约（自动创建订单）
**接口**: `PUT /bath/appointment/confirm/{appointmentId}`
**业务逻辑**:
- 商家确认预约可以提供服务
- 更新预约状态为 `confirmed`（已确认）
- **自动创建订单**，订单状态为 `unpaid`（待支付）
- 订单总金额 = 预约的预计价格
- 订单关联预约ID（appointmentId）
- 生成订单号（orderNo）

**代码位置**: `PetBathAppointmentServiceImpl.confirmAppointment()`

**关键代码逻辑**:
```java
// 1. 检查预约状态
if (!"pending".equals(appointment.getStatus())) {
    throw new RuntimeException("预约状态不正确，无法确认");
}

// 2. 检查是否已存在订单
PetBathOrder existOrder = bathOrderMapper.selectBathOrderByAppointmentId(appointmentId);
if (existOrder != null) {
    throw new RuntimeException("该预约已存在订单");
}

// 3. 更新预约状态
appointment.setStatus("confirmed");

// 4. 创建订单
PetBathOrder order = new PetBathOrder();
order.setAppointmentId(appointmentId);
order.setTotalAmount(appointment.getExpectedPrice());
order.setStatus("unpaid");
```

### 3. 用户支付订单
**接口**: `PUT /bath/order/pay/{orderId}`
**业务逻辑**:
- 用户支付订单
- 更新订单状态为 `paid`（已支付）
- 记录支付时间（payTime）
- 更新已支付金额（paidAmount = totalAmount）

**代码位置**: `PetBathOrderServiceImpl.payOrder()`

**关键代码逻辑**:
```java
// 1. 检查订单状态
if (!"unpaid".equals(order.getStatus())) {
    throw new RuntimeException("订单状态不正确，无法支付");
}

// 2. 更新订单状态
order.setStatus("paid");
order.setPaidAmount(payAmount);
order.setPayTime(new Date());
```

### 4. 开始服务
**接口**: `PUT /bath/appointment/start/{appointmentId}`
**业务逻辑**:
- 商家开始为宠物提供服务
- **检查订单是否已支付**（只有已支付的订单才能开始服务）
- 更新预约状态为 `in_service`（服务中）
- **同步更新订单状态为 `in_service`**

**代码位置**: `PetBathAppointmentServiceImpl.startService()`

**关键代码逻辑**:
```java
// 1. 检查预约状态
if (!"confirmed".equals(appointment.getStatus())) {
    throw new RuntimeException("预约状态不正确，无法开始服务");
}

// 2. 检查订单是否已支付
PetBathOrder order = bathOrderMapper.selectBathOrderByAppointmentId(appointmentId);
if (!"paid".equals(order.getStatus())) {
    throw new RuntimeException("订单未支付，无法开始服务");
}

// 3. 同步更新预约和订单状态
appointment.setStatus("in_service");
order.setStatus("in_service");
```

### 5. 完成服务
**接口**: `PUT /bath/appointment/complete/{appointmentId}` 或 `PUT /bath/appointment/complete/{appointmentId}/{actualPrice}`
**业务逻辑**:
- 服务完成，确认实际价格（可能和预计价格不同）
- 更新预约状态为 `completed`（已完成）
- **同步更新订单状态为 `completed`**
- 记录实际价格（actualPrice）
- 更新订单总金额为实际价格
- **处理价格差异**：
  - 如果实际价格 > 已支付金额，需要补差价（TODO）
  - 如果实际价格 < 已支付金额，需要退款（TODO）

**代码位置**: `PetBathAppointmentServiceImpl.completeServiceWithPrice()`

**关键代码逻辑**:
```java
// 1. 确定实际价格
BigDecimal finalPrice = actualPrice != null ? actualPrice : appointment.getExpectedPrice();

// 2. 更新预约状态和实际价格
appointment.setStatus("completed");
appointment.setActualPrice(finalPrice);

// 3. 同步更新订单状态和总金额
order.setStatus("completed");
order.setTotalAmount(finalPrice);

// 4. 处理价格差异
BigDecimal difference = finalPrice.subtract(paidAmount);
if (difference > 0) {
    // 需要补差价
} else if (difference < 0) {
    // 需要退款
}
```

## 二、异常流程

### 1. 取消预约（在确认前）
**接口**: `PUT /bath/appointment/cancel/{appointmentId}`
**业务逻辑**:
- 更新预约状态为 `cancelled`（已取消）
- 记录取消原因和取消时间
- **不创建订单**（因为还未确认）

### 2. 取消订单（在支付后，服务前）
**业务逻辑**:
- 更新订单状态为 `cancelled`
- 更新预约状态为 `cancelled`
- 触发退款流程（TODO）
- 更新订单状态为 `refunded`
- 记录退款金额

## 三、状态流转图

### 预约状态流转
```
pending（待确认）
    ↓ 商家确认
confirmed（已确认）
    ↓ 开始服务
in_service（服务中）
    ↓ 完成服务
completed（已完成）

pending → cancelled（已取消）
confirmed → cancelled（已取消）
```

### 订单状态流转
```
unpaid（待支付）
    ↓ 用户支付
paid（已支付）
    ↓ 开始服务
in_service（服务中）
    ↓ 完成服务
completed（已完成）

unpaid → cancelled（已取消）
paid → refunded（已退款）
```

## 四、数据库关联

- `pet_bath_order.appointment_id` → `pet_bath_appointment.appointment_id`
- **关系**: 一个预约对应一个订单（1:1关系）
- **创建时机**: 预约确认时自动创建
- **状态同步**: 订单状态变化时，同步更新预约状态

## 五、关键业务规则

1. **订单创建时机**: 预约确认时自动创建订单
2. **价格处理**:
   - 预计价格（expectedPrice）：预约时根据体重计算
   - 实际价格（actualPrice）：服务完成后确定
   - 订单总金额（totalAmount）：初始等于预计价格，服务完成后更新为实际价格
3. **状态同步**: 预约和订单状态需要保持同步
4. **支付前置条件**: 订单创建后，用户才能支付；支付成功后，才能开始服务
5. **事务处理**: 所有状态变更操作都使用 `@Transactional` 确保数据一致性

## 六、API接口汇总

### 预约相关接口
- `POST /bath/appointment` - 创建预约
- `PUT /bath/appointment/confirm/{appointmentId}` - 确认预约（自动创建订单）
- `PUT /bath/appointment/start/{appointmentId}` - 开始服务
- `PUT /bath/appointment/complete/{appointmentId}` - 完成服务
- `PUT /bath/appointment/complete/{appointmentId}/{actualPrice}` - 完成服务（带实际价格）
- `PUT /bath/appointment/cancel/{appointmentId}` - 取消预约

### 订单相关接口
- `PUT /bath/order/pay/{orderId}` - 支付订单
- `GET /bath/order/byAppointment/{appointmentId}` - 根据预约ID查询订单
