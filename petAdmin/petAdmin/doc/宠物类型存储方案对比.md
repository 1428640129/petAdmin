# 宠物类型存储方案对比

## 方案对比

### 方案1：使用英文字符串（当前实现）
- `long_hair` = 长毛
- `short_hair` = 短毛

**优点**：
- 可读性强，直接看数据库就知道含义
- 不需要查字典或注释
- 代码中可以直接使用有意义的字符串

**缺点**：
- 占用存储空间较大（varchar(20)）
- 与项目中其他字段（status用0/1）不一致
- 如果类型很多，字符串可能变长

### 方案2：使用数字（推荐，与项目一致）
- `0` = 短毛
- `1` = 长毛

**优点**：
- 占用存储空间小（tinyint或char(1)）
- 与项目中其他状态字段保持一致（status用0/1）
- 查询性能略好
- 符合项目编码规范

**缺点**：
- 需要查字典或注释才知道含义
- 代码中需要用数字，可读性稍差（但可以通过常量或枚举解决）

## 项目中的实际做法

查看项目中其他字段，都使用数字：
- `status`: `0=正常,1=停用`
- `是否已读`: `0=未读,1=已读`
- `业务类型`: `0=其它,1=新增,2=修改...`

## 建议

**推荐使用数字方案**，原因：
1. **保持一致性**：与项目中其他字段保持一致
2. **节省空间**：使用 `char(1)` 或 `tinyint` 更节省
3. **性能更好**：数字比较比字符串比较快
4. **扩展性好**：如果以后要加类型（如 `2=中毛`），数字更灵活

## 实现建议

如果使用数字，可以这样实现：

### 数据库字段
```sql
ALTER TABLE `pet_bath_appointment` 
MODIFY COLUMN `pet_type` char(1) DEFAULT '0' COMMENT '宠物类型（0=短毛,1=长毛）';

ALTER TABLE `pet_bath_service_price` 
MODIFY COLUMN `pet_type` char(1) DEFAULT '0' COMMENT '宠物类型（0=短毛,1=长毛）';
```

### Java代码中使用常量
```java
public class PetTypeConstants {
    /** 短毛 */
    public static final String SHORT_HAIR = "0";
    /** 长毛 */
    public static final String LONG_HAIR = "1";
}
```

### Excel导出配置
```java
@Excel(name = "宠物类型", readConverterExp = "0=短毛,1=长毛")
private String petType;
```
