## 核心功能说明

### 1. 价格计算逻辑

**支持长毛/短毛不同价格**:
- 价格表按 `service_id` + `pet_type` + `weight_min/max` 查询
- 长毛（1）和短毛（0）可以有不同的价格梯度
- 如果找不到匹配的价格，返回0

### 2. 商家修改宠物信息

**业务规则**:
- 只有在 `pending`（待确认）或 `confirmed`（已确认但未支付）状态下可以修改
- 如果订单已创建且未支付，会自动更新订单价格
- 如果订单已支付，价格无法修改（返回提示信息）

**接口调用**:
```json
PUT /bath/appointment/updatePetInfo/123
{
  "petWeight": 6.5,
  "petType": "1"
}
```

**返回结果**:
```json
{
  "success": true,
  "newPrice": 128.00,
  "oldPrice": 98.00,
  "orderUpdated": true,
  "message": "价格已更新"
}
```

### 3. 自动价格计算

**创建预约时**:
- 如果用户未提供预计价格，系统自动根据体重和类型计算
- 如果用户未提供宠物类型，默认使用 `0`（短毛）

**确认预约时**:
- 系统会重新计算价格，确保价格准确
- 如果价格有变化，自动更新预约的预计价格
- 创建订单时使用最新计算的价格

## 使用流程

### 场景1：用户提交预约时填写错误
1. 用户提交预约（体重5kg，类型0=短毛）
2. 商家查看预约，发现实际是6.5kg长毛（1=长毛）
3. 商家调用 `updatePetInfo` 接口，传入 `petType: "1"`
4. 系统重新计算价格（从98元变为128元）
5. 如果订单未支付，自动更新订单价格
6. 用户支付新价格

### 场景2：确认预约前修改
1. 用户提交预约（体重可能不准确）
2. 商家在确认前修改体重和类型
3. 确认预约时，系统使用最新信息创建订单

## 注意事项

1. **执行SQL脚本**: 需要先执行 `sql/update_appointment_add_pet_type.sql` 更新数据库表结构
2. **价格配置**: 需要在价格表中为长毛和短毛分别配置价格梯度
3. **状态限制**: 只有在特定状态下才能修改宠物信息
4. **订单同步**: 如果订单已创建，修改价格时会同步更新订单
